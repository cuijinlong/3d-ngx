# 拓扑与地址细节

## 1. 两条通道（务必区分）

### 通道 A：公网直连（默认，无中转）

```
Mac ──SSH 直连──▶ 124.220.77.179   (国泰, OpenCloudOS 9.6)
Mac ──SSH 直连──▶ 49.234.181.201   (金诺, Ubuntu 22.04)
Mac ──SSH 直连──▶ 150.158.41.155   (中转, Ubuntu 24.04)
```

- 用于：**Mac 执行 124/49/150 上的任务**（这是默认路径）
- 特点：点对点，**不经过 150 转发**，链路最短、延迟最低
- 前提：三台都有公网 IP 且 sshd 可达

### 通道 B：WireGuard 星型内网（特殊/反向）

```
              ┌────────────────────────────┐
              │ 150 总机  wg0 10.88.0.1/24 │
              │ udp/51820   ip_forward=1   │
              └──┬────────┬──────────┬─────┘
                 │        │          │
        10.88.0.4│ 10.88.0.2│  10.88.0.5 / .6
             124国泰    49金诺     Mac / Windows（NAT 后）
```

- 用于：① 服务器 → Mac/Windows（NAT 后只能靠隧道反连）② 直连受阻时的兜底 ③ 未来新增机器的统一内网
- **注意：peer 之间（如 Mac↔124）的流量由 150 内核转发**，所以它不是"免中转"通道。

## 4. SSH 密钥（四台已全互联）

每台机器的 `authorized_keys` 都含其余三台 + 自己的公钥，可免密互访。身份注释：`macmini`（Mac）、`jinnuo49`（49）、`dsh-newbox`（150）、124 为无注释 ed25519。

## 5. 策略优先级（用户明确要求）

1. **Mac → 124/49/150：直连优先，能直连就不要中转。**
2. 150 只在"特殊情况"中转：直连被网络阻断、需要对 NAT 后的机器发起连接、跨机转发。
3. **124 绝不做中转**（`ip_forward=0`，结构上也不允许）。
4. 49 同理不做中转。
