# 3D-NGX 工作台布局方案（修订 · schema 收口）

给前端对照实装。本方案只定界面与绑定语义。产品名只用 **3D-NGX**，主色 `#1657e8`，浅色工业风（savehmi），不要能源卫士绿，不要 Savior 品牌。产品是可视化加绑定，不是场景编辑器。

这一版把 schema 当作前端、后端、GLB 的联通桥梁：可绑定的对象、行为、看板数据，必须从当前导入的 GLB 里按 schema 动态读出（Savior 导出的 `extras.hmi`，本模型为 `hmi-scene/1`），按这个对象在模型里实际有的参数来列。不要在界面或代码里写死设备名、测点或行为。

仍遵守：右侧配置方式跟平台仪表板「目标设备 / 行为」那套字段走；测点仍可用中英对照表自动匹配，设备别名仍然不用，只直接选择实时设备；左侧「可连接 / 设备列表 / 模型」不加回。只绑实时设备。

对照：稿图在 `mocks/`，可预览页面在 `preview/index.html`。本版把启停和状态改到底部上浮抽屉（浏览、编辑、运行三态都保留），浮动铭牌改为指向或选中才显示，预览 / 浏览 / 运行态下右侧栏整栏不出现、画布向右铺满，点顶栏「编辑」才在右侧出现绑定配置。文中「模块机 8#」「风扇转动」「温度 ℃」「XV-101」「L-101-1」以及 `temperature`、`fan_running`、`valve_open` 等键只是天骄科技园.glb 的示例，不是唯一正确值；换一个模型、换一台实时设备，就要换成当时读到的内容。

本版已按平台架构师的思路补上指令下达（RPC）配置。下发走平台已有的 RPC V2，不要另做一套指令下达 API，也不要改去写属性。平台组态「某市热力 · 二号换热站组态」这份实例里，阀门和热泵实际配的是设置属性；3D-NGX 仍按已确认方案走 RPC。接口细节见第 12 节，来源 `/workspace/tianjiao-rpc-for-frontend.md`。

已确认约定（与早前建议冲突时，以这里为准）：

1. 三通和弯头也要能作为目标设备。默认可不占铭牌，但必须能选中，并允许手动绑到平台实时设备。选中后没有行为和看板数据时，不出那两节，只保留对象名并说明，仍可绑目标设备。
2. 阀门开关两者都允许，由用户选：可以当遥测驱动的状态动画，也可以当可下发命令；可只配一种，或两种都配。
3. 管流和仪表开关要能单独绑定，不是只按规则派生；没有独立绑定时，才走文件里 6 条 rules 的默认联动。
4. 不按远程方法列表生成启停；只给满足条件的对象在底部控制面板出启动 / 停止，不放进右侧行为表。判断依据是该对象有控制面板和屏幕零件，不要写死台数或型号。本模型恰好是 9 台模块机，这是实例，不是规则。
5. 测点仍可用中英对照表自动匹配；设备别名仍然不用。
6. 泵和 PLC 只按名称手动绑定，允许把摆针、柜门等视觉动作绑到用户指定的遥测键。没有 `data` 就不要出现看板数据节。
7. 控制面板和屏幕不单独绑定，不可点选为独立对象，只作为「这台模块机底部控制面板是否出启停」的条件。只绑实时设备。
8. 浮动铭牌（以及泵、PLC 的轻量连接状态签）默认不显示。只在鼠标指向或点击选中该对象时显示；指针移开且该对象不再被选中后，铭牌消失。未指向也未选中的设备，画面上不要出现它的铭牌。
9. 预览、浏览和运行态下右侧栏整栏不出现，画布向右铺满，不要空态占位，也不要「实时检测」「历史数据」选项卡，不要为告警或测点再留右侧栏。「编辑」放在顶栏，与「隐藏测点」等并列；点「编辑」后右侧才出现现行的目标设备 / 行为 / 看板数据配置。编辑态顶栏按钮变为「退出编辑」，栏头也可保留同样出口。退出后右侧栏消失，回到浏览。底部抽屉在浏览、编辑、运行三态都保留。

## 1. 工作台总布局（不变）

最左侧产品导航保留（首页 / 工作室 / 运行 / 搜索 / 设备 / 设置）。中间是三维画布：预览、浏览和运行态下画布向右铺满，不留右侧栏；只有编辑态才在右侧出现连接配置。不要把「可连接 (197)」「设备列表」「模型」加回画布左侧。旧的「可连接 197」把解析器合成的启停、控制面板和屏幕也算进去了，不要再用这个数字当对象总数。本模型画面里可点选的 HMI 对象是 109 个（32 台设备含三通弯头 + 13 阀 + 2 仪表 + 40 段管道 + 22 个管配件），不含 18 个控制面板 / 屏幕零件。

顶栏保留「查找画面对象」（用完即关的浮层），用来代替左栏定位，列表同样从 schema 动态来，须能找到模块机、泵、柜子、阀门、管道、仪表、三通、弯头和管配件。不要出现移动 / 旋转 / 缩放。「按名称自动连接」仍是次要入口。「按模型创建模拟设备」不要出现。进入绑定配置的「编辑」放在顶栏已有动作里，与「隐藏测点」等并列；不要在画布右缘放折叠箭头或空栏占位。

漂浮看板画在对应对象头顶，展示该对象已经绑上的看板数据（名称、运行徽标、已绑遥测）。铭牌上不再画启动 / 停止，启停改在底部控制面板，见第 7 节。浮动铭牌默认不出现：只在鼠标指向或点击选中该对象时显示，失去焦点（指针移开且不再选中）后消失。未指向也未选中的设备不要常驻铭牌。没有测点、也没有动作的对象（本模型里的三通、弯头、管配件）即使选中也不占铭牌。

控制面板和屏幕不可点选为独立对象，也不出现在「查找画面对象」列表里。画面上点到这些零件时，选中它所属的那台模块机。它们只作为「这台模块机底部控制面板是否出启停」的条件，不要再绑一套目标设备。

## 2. Schema 是联通桥梁

打开或导入画面时，解析器必须先认出场景文档，再按 schema 的约束和范式列出可绑定项。前端、后端和绑定存储都只消费这一次解析的结果，不要各自再写一份设备名或测点表。

1. **权威场景文档**在根节点（本模型是名称「天骄科技园」的 `nodes[0]`）的 `extras.hmi`。必有字符串字段 `schema`（本模型为 `hmi-scene/1`）。`asset.extras.hmi` 只有导出元数据，没有 `devices` / `actions` / `data`，不能当绑定清单。不要把 `hmiSnapshot` 当作权威源，每次打开都必须从文件重新解析。
2. 本 schema **靠层级和字段名区分**含义，没有统一的 `type: "action"|"telemetry"` 标签。顶层只有 `devices` / `pipes` / `valves` / `instruments` / `fittings` / `rules`，没有顶层 `actions` 或 `data` 数组。行为和看板测点都嵌在对象上。
3. **对象主键是 `node`**，等于 glTF 节点名，全局唯一，也是绑定位。`SceneDocument.bindings` 的 `sceneEntityId` 必须能反查到 `node`。绑定写在场景文档里，不写回 GLB，不改节点位置，也不改 `data[].val`。
4. **看板测点只来自 `devices[].data[]`**（`name` + 字符串 `val`，可选 `unit`）。`val` 是导出占位，绑定后必须用所选实时设备的时间序列，不能把 `25.0` 当成现场值。没有 `data` 这个键，表示该对象没有可绑看板数据，不是解析失败，也不要编造温度、功率。
5. **设备视觉行为来自 `devices[].actions[]`**（`id` / `label` / `clip` / `on`）。定位靠 `(node, id)`，同一 `id`（如 `blink:led`）可以出现在不同对象上，不能按 id 全局去重。`id` 不是平台命令 id。
6. **阀门、仪表、管道没有 `actions` / `data` 数组**，可绑定项来自它们在 schema 里实际有的字段：阀门的 `clips.open` / `clips.close` 与布尔 `open`；仪表的 `clips.on` / `clips.off`；管道的 `flow.clip`。这些是 schema 里的动画与状态，不是解析器临时编出来的业务命令。文件里的 6 条 `rules` 仍有效，见第 5.2 节。
7. **解析器不要往行为列表里塞 extras.hmi 没有的项。** 不要把合成的 `start` / `stop` 当成模型行为，也不要为控制面板、屏幕各做一套独立 bindable。底部控制面板的启停按第 7 节的条件出现，不按 `rpcMethods` / `listCommands` 自动生成行。
8. 若没有 `extras.hmi`，或 `schema` 不是已识别的场景文档，不能假装有测点，也不要用全部 glTF 节点去生成一份假的可绑清单。

## 3. 右侧栏：只在编辑态出现

预览、浏览和运行态下，右侧栏整栏不出现：不要空态占位，也不要「实时检测」或「历史数据」两个选项卡，不要为告警或测点再留右侧栏。画布向右扩展，填满原先右侧栏的空间，不要留一条空白占位，也不要在画布右缘放折叠箭头。浏览态与运行态在右侧这一点上一致。

「编辑」入口放在顶栏已有动作里，与「隐藏测点」等并列，不要在画布右缘另做入口。点「编辑」进入**编辑态**后，右侧才出现下面这套绑定配置（目标设备 / 行为 / 看板数据，字段口径不变）。编辑态下，顶栏该按钮变为「退出编辑」，右侧栏头也可保留同样出口。只有点「退出编辑」（顶栏对应按钮或右侧栏头）或「完成」才退出编辑态：右侧栏消失，回到浏览态，画布重新铺满。点画布空白不退出编辑，只清除当前选中、收起该对象的铭牌，并缩回底部抽屉；编辑态下右侧绑定栏仍留着。

底部设备状态和动作抽屉在浏览、编辑、运行三态都要保留，不因右侧绑定栏出现或消失而拿掉。详见第 7 节。

未选对象时不要先摊开绑定表；要配置绑定，仍先点顶栏「编辑」。进入编辑态后若尚未选中对象，右侧说明在画面上点要连接的对象即可，不要用「实时检测 / 历史数据」空态去占栏。「按名称自动连接」仍是顶栏查找的次要入口。

「演示数据」只标在状态栏（顶栏也可保留演示标记），不要和现场值混在一起。

不要拆成互不相干的几套配置，也不要用问句栈。编辑态下，选中画面对象后按该对象在 schema 里实际有的项出现下面几节：

```
{对象名称}                 例如：模块机 8#（从模型读取）

目标设备
  [ TJ-Module-08                    × ]
    模块机 · 实时

行为                         来自该对象的 actions，或阀 / 表 / 管上读到的开关、流动
  风扇转动      使用时间序列“fan_running”     编辑

看板数据                     来自该对象的 data；没有 data 就不要这一节
  温度 ℃       使用时间序列“temperature” 自动   编辑

底部控制面板                 仅当该对象有控制面板和屏幕时出现启停，不是行为行
  该对象的底部控制面板提供启动 / 停止，不按远程方法列表生成。

解绑
```

平台组态符号上写死的五行（运行中 / 警告状态 / 严重状态 / 严重状态动画 / 点击）不要搬到 3D-NGX 当固定列表。

进入编辑态后，已选但还没定目标设备时，仍按模型列出「行为」和「看板数据」，行先空着、不可编辑，直到选出一台实时设备。模型里没有行为，就不要出现「行为」这一节；没有 `data`，就不要出现「看板数据」这一节。两者都没有时（三通、弯头、管配件），只保留对象名称和「目标设备」：这个对象在模型里没有可绑定的行为或看板数据，但仍可选择目标设备。不要把三通、弯头排除在可绑定对象之外。

## 4. 目标设备

这一版只保留直接选择设备。不要「设备 | 实体别名」分段开关，不要别名摘要，也不要别名编辑弹层。不能靠「这台模块机又名某某」去自动对上平台设备。

目标设备就是一个搜索下拉，只列平台里的实时设备（以 `additionalInfo.deviceVirtual` 为准：`virtual` / true / 1 为虚拟，`real` 或缺失为实时）。选定后显示设备名称和「实时」标记，可以清除后重选。下拉里的名字来自平台，不要写死。

「按名称自动连接」只做当场名称 / 位号比较：模块机可用非空位号（如 `1#`）和名称去建议；泵和 PLC 没有位号，只按名称手动或精确匹配，不要用型号把多台同型号设备配错。三通、弯头、管配件不要靠模糊名去猜，对不上就留给手动。一对多或对不上就不要猜。

## 5. 行为

每一行的标题就是该对象在模型里的动作名（如「风扇转动」「压力表指针摆动」「打开阀门」「管道流动」），摘要和编辑入口的写法跟平台行为行一致，不要改成问句。点编辑，打开锚定在该行的轻量弹层（不必用抽屉），标题就是该行为名，底部是「取消 / 应用」。点应用才写入。

视觉类行为（模块机的风扇 / 指示灯，泵的摆针，柜子的柜门 / 指示灯，以及管流、仪表开关的遥测侧）字段跟平台状态类行为同一套，按所选「操作」显示：

- 操作：不执行操作、获取属性、获取时间序列、获取告警状态
- 选「获取时间序列」时：时间序列键*（从当前设备读，可搜索）、操作结果转换器（无 / 函数）、当结果为「{行为名}」时（类型「布尔值」，值 True / False）
- 选「获取属性」时：属性范围、属性键*、转换器、当结果为「{行为名}」时
- 选「不执行操作」时：只给一个值 True / False
- 选「获取告警状态」时：按平台该项的字段走

平台里的「获取仪表板状态 ID / 获取仪表板状态对象」不要出现。不要把「操作」改名叫「做法」，不要把「时间序列键」改名叫「选择测点」，不要把 True / False 改成「是 / 否」。

「函数」转换在界面里要保留「无 / 函数」，和平台一致。函数脚本怎么落地仍先讨论，未实现前选「函数」可提示暂未支持。不要另造「打开设备详情」，也不要把平台那套仪表板导航点击搬过来。

泵和 PLC 选中目标设备后，允许把 `swing:gauge`、`swing:door`、`blink:led` 绑到用户指定的遥测键，并填写「当结果为…时」。不要因为动作 id 不叫 `spin` / `blink` 就丢掉这一行，也不要给泵、柜子编造看板测点。

### 5.1 阀门：遥测驱动动画和可下发命令，由用户选

阀门的行为行仍来自该阀在 schema 里的开关 clips，不要写死「打开阀门 / 关闭阀门」这几个字到代码常量里（标题按解析到的标签显示）。每一行都可以配两种用途，可只选一种，或两种都配：

- **遥测驱动动画**：字段与上面的视觉行为相同，用平台测点驱动 open / close 片段（按画面规则，开关类片段只播一次）。
- **下发命令**：从当前选中的那台实时设备即时读取可下发命令（`listCommands`），由用户手选要下发的那一条。命令 id 和名称都不要写死。这里是「用户给这条模型开关指定一条命令」，不是按远程方法列表给所有对象自动生成启动 / 停止。

弹层顶部增加一项「绑定方式」，用两个可同时勾选的选项：**遥测驱动动画**、**下发命令**。勾上哪一项，下面就出现哪一组字段；两组都勾就两组都显示。不要把「下发命令」塞进「操作」下拉里冒充平台原有选项。摘要里已配的部分都要写出来，例如：`使用时间序列“valve_open” · 下发命令“open”`。其中命令名用当时选中命令的标签或 id，示例键不是唯一正确值。

命令清单来自当前已绑实时设备的 `listCommands`。平台没有名为 `listCommands` 的 REST，现有适配器是读设备属性 `rpcMethods`（依次试服务端 / 共享 / 客户端范围）。不要和属性 `rpcCommands` 混用。下拉展示命令标签，写入绑定的是命令 id，以及它声明的参数形状；无参数则传空对象 `{}`，不要编造参数。命令 id 和名称都不要写死为 `open` / `close`。

本机库当前没有阀门设备，也没有阀专用命令。阀门要下发，只能绑到一台有命令的实时设备（例如模块机、泵、PLC）再手选一条。若列表为空，下拉为空、该项不可用，不要在前端编造命令。已选命令后来从列表里消失时，保留已选 id 但标失效，提示重新选择，不要静默改成别的命令。

管流、仪表开关按 5.2 只绑遥测，不在这节做下发命令。三通 / 弯头可以选目标设备，但没有 clips 就不要生成行为行或下发配置，也不要因为目标设备有命令目录就给它们加行。泵和 PLC 清单里的启动 / 停止只作为手选选项，不要自动画成底部控制面板启停。

### 5.2 管流和仪表开关：可单独绑定，规则作默认联动

管道流动、仪表开启 / 关闭必须作为该对象自己的行为行，允许单独绑定到用户指定的遥测键，配置方式与视觉行为相同。不要只靠规则派生、让它们在右侧消失。

文件里的 `rules` 仍然有效：未给某段管流或某块仪表做独立绑定时，运行时仍可根据已绑定阀门的开闭和规则自动播放；一旦用户做了独立绑定，以绑定为准。右侧在这一节下面用一句短说明标出：「未单独绑定时，按画面规则随阀门开闭联动；单独绑定后以这里为准。」

## 6. 看板数据

这一节专门绑定漂浮看板上要显示的遥测，字段列表等于该对象 `data[]`，不要再做一套「头顶显示哪些数」的开关。绑上的项按顺序出现在铭牌里（实现上可沿用现有上限，但显示哪些字段仍以绑定结果为准，而不是代码里写死温度、功率）。铭牌仍可显示已绑遥测和「运行」状态徽标，但不要再画启动 / 停止按钮。铭牌本身按第 7 节显隐，不要常驻。

点编辑，弹层标题就是该字段名（如「温度 ℃」）。数字类字段主要是取值，不需要「当结果为 True / False」：

- 操作：不执行操作、获取属性、获取时间序列
- 选「获取时间序列」时：时间序列键*、操作结果转换器（无 / 函数）
- 选「获取属性」时：属性范围、属性键*、转换器

「运行状态」这类状态字段如果本身是看板数据，也按取值绑定；铭牌上的运行 / 停止标记由这条已绑定的状态数据得出，不要再单独写死一行「运行中」。

选出目标设备后，**可以用中英对照表给测点做自动建议**（例如温度 ↔ `temperature`、功率 ↔ `power`）。对照表只用于测点，不是设备别名，也不要用它去自动连接设备。建议成功时，行上预填对应键，并标「自动」；用户可以改或清掉。对不上（平台没有这个键，或同一个名字对上不止一个点）就留空，让用户手选，不能把对照结果当成一定存在的点。本模型里「开度」「运行状态」尤其可能对不上平台字典，必须允许手选。

看板取值一律用绑定后的平台数据。缺测点、空值或订阅失败时显示「暂无数据」，不要回退成把模型里的样例 `val` 当成现场值。

## 7. 底部控制面板（启停与状态）

启动 / 停止不出现在「行为」表里，也不按该设备的 `rpcMethods` / `listCommands` 自动生成一行。这取代了早先「启停做在铭牌上」的摆放，只改摆放和交互，绑定规则不变。不要在画布左下角放一组全局启停条，也不要把启停按钮画回铭牌。

### 7.1 交互与结构

点画面对象（含点到所属模块机的控制面板或屏幕）时，这块面板像抽屉一样从场景底部上浮；点空白或失去焦点后缩回去，只留一个细提手（以稿图 `workbench-search` 为准），不要再展开一排空的启动 / 停止。悬停只出铭牌，不抬起抽屉。点画布空白只清除当前选中、收起铭牌并缩回抽屉，不退出编辑态；右侧绑定栏仍留着，只能点「退出编辑」（或顶栏对应按钮）或「完成」才退出。这块面板在浏览、编辑、运行三态都保留，不因右侧绑定栏出现而撤掉。面板是浅色卡片，圆角、淡阴影，顶部中间有细小抽屉提手，横坍在中间画布底部、放在 28px 状态栏之上，水平居中于当时的画布区；编辑态下不要盖住右侧栏，浏览和运行态没有右侧栏，抽屉在加宽后的画布里居中。「总览」fab 仍在画布右下（right: 16px; bottom: 40px），不要被面板挡住。

面板结构借鉴用户标注的底部 HUD，用 savehmi 浅色工业风实现，不要照搬深色玻璃风格，也不要换场景。稿图里的三行是参考样式：

1. 设备控制（启动 / 停止，或说明该对象不提供启停）以及当前选中名。未选中时写「未选中设备」，并且不要画出启动 / 停止键（连禁用态也不画）。设备数据（未绑定时写「未绑定」，已绑定可给简要值或「已绑定」）。
2. 运行状态 chips。图上「停止 / 运行 / 故障 / 报警 / 检修 / 备用」是参考样式，种类由解析器和绑定结果决定，不要写成唯一固定集。空态用「—」。
3. 汇总：运行设备、设备总数、系统告警、总消耗量。稿图可用本模型的实例数字（天骄科技园.glb 恰好 32 台设备：9 模块机 + 2 泵 + 2 PLC + 18 三通 + 1 弯头），这是解析结果，不是写死常量。未选中时，不依赖选中对象的汇总数可以出解析到的值（如设备总数 32），其余可用「—」。

面板里出现什么，必须由解析器和绑定结果统一决定，不能写死台数、型号或状态项。本模型恰好 9 台带控制面板和屏幕的模块机，那是实例不是规则。

未选中、未绑定时，面板里要能看出空态（沿用「未选中设备」「未绑定」、状态花签和汇总区这类提示）。未选中的展开空态不要画出启动 / 停止键，包括禁用态。稿图 `workbench-empty` 为展开空态，便于对照；失去焦点后缩回，只留细提手，以 `workbench-search` 为准，不要展开一排空的启动 / 停止。

满足条件时，右侧编辑态用一句短说明标出「该对象的底部控制面板提供启动 / 停止」。

### 7.2 启停出现条件与命令匹配

判断依据是 schema：这台设备带有控制面板和屏幕零件。本模型里只有 9 台风冷冷水模块机满足条件，因此只有选中它们时底部面板出启停。不要把「9 台」「HMI3D-0004」或设备名写进判断逻辑；换一个没有这些零件的模型，就不要出启停。

按钮画出来之后，能不能按、按下发谁，完全由当前已绑的那台实时设备、此刻的命令列表决定。选定或更换目标设备时算一次，运行期点击前再拉一次（或沿用很短的缓存）。不要写死只能是 `start` / `stop` 这两个英文 id，也不要为此在右侧行为表里自动生成行。

匹配规则（启动、停止各自找一条）：

1. 先丢掉带必填参数的命令，避免误发一条缺参数的请求。
2. 看标签或 id 是否含「启动」（停止键则含「停止」）。不要仅因含「启」就命中「启停」。英文 id 大小写不敏感地等于 `start` / `stop`，可作为同等条件。
3. 仍有多条时：优先 id 恰好为 `start`（或 `stop`）的那条；再不行取标签更短、id 里不含 `:` 的。还分不出，当作匹配失败。
4. 一条都没有、未选目标、目标已变成虚拟设备、或命令列表读失败：按钮不可用，并说明原因（未绑定 / 没有对应命令 / 绑定已失效 / 命令列表暂时读不到）。不要用上次别的设备的匹配结果。

对得上就下发该条 id 和它声明的参数（无参数传 `{}`）。进行中禁用按钮。下发走第 12 节的 RPC V2；成功只表示已经送出，失败把超时或错误显示在底部面板附近。按本机模块机的清单，这套规则会落到无参数的「远程启动」「远程停止」，而不会误用带布尔参数的「启停」`setRunning`。

铭牌上的「运行」只是状态标记，由已绑定的运行状态得出；「演示数据」只放在状态栏，不要在铭牌或底部面板上做成和启停同类的操作按钮。不要为了「看起来有启停」去改 GLB，也不要把合成的 `start` / `stop` 假装成 extras.hmi 字段。

泵、PLC、阀门、管道、三通 / 弯头、管配件都不要出启停。选中它们时底部面板可以上浮，但设备控制处应写明该对象没有控制面板和屏幕、不提供启停。泵和 PLC 没有看板 `data`，画面上只用轻量连接状态签（已连接 / 未连接），不要套模块机那套遥测看板；这些连接签同样遵循下面的显隐规则。

### 7.3 铭牌显隐

浮动铭牌不能一直显示。只在鼠标点击或指向该设备时显示，失去焦点后不显示。

- 未指向也未选中的设备：画面上不要出现该设备的浮动铭牌。未选中状态尤其要看得出：一排铭牌不要再常驻。
- 鼠标指向或已点击选中的那一台：才显示它的铭牌。铭牌仍只含名称、运行徽标、已绑遥测，没有启动 / 停止按钮。
- 失去焦点（移开指针且不再选中）后铭牌消失。
- 泵 / PLC 的轻量连接状态签同样遵循这条显隐，不要常驻。
- 显示名仍是「模块机 9#」，不要写成「模块机 9 9#」。

稿图里：`workbench-empty` 不出现任何铭牌，只留底部空态面板，无右侧栏；`workbench-bound` 只留模块机 9# 的铭牌，其它模块 / 泵 / PLC 的牌都去掉，无右侧栏；`workbench-bound-edit` 在编辑态仍保留这块 9# 铭牌和底部抽屉，并出现右侧绑定栏。

## 10. 数据与解析时要注意的

数据仍建议在现有 `DeviceBinding` 上增量：`deviceId` / `deviceName` 表示选中的实时设备；`actionMappings` 对应模型行为（`actionId` 用 extras 里的动作 id，或阀 / 表 / 管上读到的开关、流动 id；阀门若配了下发，再写 `commandId`，建议同时存当时的标签，仅供摘要显示）；`telemetryMappings` 对应看板数据（`field` 用 extras 里的数据名，例如「温度」）。底部控制面板的启停不要写成绑定里的固定命令 id，运行时按第 7 节当场匹配。先不要加 `targetMode`、`aliasName`。不要把行为做成写死的「运行中 / 警告 / 点击」枚举。

设备列表继续过滤实时设备：平台列表不会只返回实时设备，「只接受实时设备」要前端和适配器自己滤。判断看 `additionalInfo.deviceVirtual`（`virtual` / true / 1 为虚拟，`real` 或缺失为实时）。时间序列键、属性键、命令列表都向当前设备实时拉取。已绑定的设备若后来变成虚拟设备，这条绑定视为无效，提示解绑重绑，不要自动改映射，也不要继续订阅或下发。

画面里不要直接拼 RPC URL，继续走现有 `DeviceDataProvider` / `DeviceCommandProvider`（`listCommands`、`sendCommand`）。命令列表失败时保留上次选项并提示错误，不要用写死的 `start` / `stop` / `open` 兜底。

解析与展示还要注意：

- `model: null`、空 `tag` 是合法值（三通 / 弯头、泵 / PLC），不要当成缺失对象。
- 管道若要用分段名，须保留 `node` 或 `seg` / `segs`，不要把多段显示成同一个 `no`。
- `悬空端` 只出现在管道 `from` / `to`，不是 glTF 节点，不要当缺失节点报错。
- 动画缺失时不播放，对象仍可显示已绑测点；不要中断整个场景。

## 12. 指令下达（RPC）配置

3D-NGX 的下发走平台已经在用的 ThingsBoard 风格服务端 RPC（V2），不是另做指令下达业务 API，也不是组态里「设置属性」那条写数通道。绑定期和运行期都继续用现有数据适配器，不要在画面里直接拼 URL。平台侧现有查询属性 + 下发 RPC 已够把绑定和运行做起来，不必为 V1 改平台代码。

### 12.1 怎么下发

- 使用 `POST /api/rpc/oneway/{deviceId}`，JSON 体至少含 `method`、`params`。`deviceId` 是平台设备 UUID。无参数时 `params` 传 `{}`。现有 `sendCommand` 就是 `{ method: commandId, params: params ?? {} }`，先不要自定义超时，也不要打开持久化。
- 不要新接已弃用的 `POST /api/plugins/rpc/oneway/{deviceId}`。双向 `twoway` 给组态取值用，底部面板启停和阀门下发不必用。
- 鉴权头是 `X-Authorization: Bearer <token>`，不是 `Authorization`。下发需要对该设备有 `RPC_CALL` 权限。
- 平台 **不校验** `method` 是否出现在命令目录里；目录是约定，不是服务端白名单。方法名来自绑定里的 `commandId`，或底部控制面板当场匹配到的那条 id，不是 extras.hmi 里的视觉动作 id（例如 `spin:fan`）。
- 单向成功 200 只表示请求已交给设备通道，不保证设备业务成功。超时、设备离线或无活动连接返回 504（体可为空）。缺 `method` 或体不合法是 400；未登录或无权限是 401 或权限错误体。失败显示在底部面板或阀门操作附近，不要静默吞掉。建议口径：504 提示「请求超时」；其它 HTTP 显示状态和平台返回的 `message`；本地提示「未绑定目标设备」「绑定已失效（虚拟设备）」「没有对应命令」。演示数据必须标明「演示」，不要和现场 RPC 混在同一条成功提示里。

### 12.2 命令清单从哪来

平台没有 `listCommands` REST。现有 `listCommands` 读的是设备属性 `rpcMethods`，请求是：

`GET /api/plugins/telemetry/DEVICE/{deviceId}/values/attributes/{scope}?keys=rpcMethods`

范围依次为 `SERVER_SCOPE`、`SHARED_SCOPE`、`CLIENT_SCOPE`，哪个先读到非空解析结果就用哪个。需要读属性权限。值可能是 JSON 数组，也可能是还要再解析的字符串，适配器两种都认。空数组或没有这个键，视为当前没有可列命令。

可接受的形状不要再发明第四种：字符串数组；对象数组 `[{ id, label?, params? }]`（`params.type` 仅为 `number` / `boolean` / `text`）；整段解析失败的纯字符串当作一条命令。非数组对象忽略，得到空列表。

不要把属性 `rpcCommands`（另一套 `{ methods:[{ method, params, desc }] }`）当成清单来源。

本机库里的实例（不是写死规则）：9 台实时模块机同时有带布尔参数的「启停」`setRunning`，以及无参数的「远程启动」`start`、「远程停止」`stop`；2 台实时泵、2 台实时 PLC 也有无参数的 `start` / `stop`（泵还有「启停」）。虚拟网关「天骄-PLC网关」也有很长的命令目录，但不能作为绑定目标。本库没有名称或类型带「阀」的设备，约 38 台其它设备没有 `rpcMethods`。换一套没有这条属性的场站，清单就会是空的——这不是前端能补的。

### 12.3 绑定期和运行期

1. 导入 GLB，从根节点 `extras.hmi` 动态列出对象、行为和看板数据；绑定写入 `SceneDocument.bindings`，不写回 GLB。
2. 拉设备分页后由前端过滤虚拟设备，再选目标。
3. 选中目标后并行拉时间序列键（测点仍可用中英对照表做自动建议）和 `listCommands`（阀门下发下拉；同时做一次底部面板启停匹配，只更新说明和按钮可用性，不往行为表插行）。
4. 运行期先确认目标仍是实时设备，否则整条绑定无效，不再订阅、不再下发。底部控制面板按第 7 节匹配后 `sendCommand`；阀门用绑定里的 `commandId`（必要时带参数）下发，若当前清单里已经没有这条，提示失效，不要改发别的。

### 12.4 核对限制和待讨论项（不阻塞这次配置，也不是 V1 前置条件）

这份接口说明来自指定 MacBook Pro 上的平台源码和本机库。当时 `energy-server` 不健康，`127.0.0.1:8090` 返回 502，没有拿到现场 REST 响应样例，也没有向设备 POST RPC。命令内容以 Postgres `attribute_kv` 为准。`rpcMethods` 的写入方在已搜索源码中未见。

下面几件事建议以后由平台 / 全栈对口径，但不要当成 V1 前置条件去改平台：把 `rpcMethods` 写成明确的数据约定（谁写、什么形状）；要不要另做正式的 `listCommands` REST；平台会不会校验 method 必须在目录里；「下发命令」要不要兼容组态那种设置属性；阀门作为独立实时设备时如何维护命令目录；单向 RPC 是否要看业务回执。
