# 3D-NGX 模板、实例与客户只读方案（草案）

给总调和用户确认用。确认前不改页面代码、不让 UI / 前端先做图表卡片、不做 git 提交。产品名只用 3D-NGX。

这份方案回答：模板和实例怎么分层、租户如何配置、客户如何只看、图表卡片和 GLB 绑定怎么按客户数据权限落下，并且不和现有场景文档、平台拓扑打成两套平行模型。

布局仍守 2026-11-21 18:18 已确认的规则：预览 / 运行右侧整栏不出现，画布铺开；只有点「编辑」才出右侧绑定配置；底部设备状态和动作抽屉在浏览、编辑、运行态都保留。此前「画面内浮动看板」只作为**客户观看界面的候选**，不是本轮先做的页面改动。

文中「模块机 9#」「天骄科技园」只是例子，换模板或换模型就要换成当时解析到的内容，不能写死。

---

## 1. 先说结论

建议做成四层，职责分开：

1. **可视化模板**：可复用的画面原型。里面是 GLB（含解析槽位）、风格套装，以及解析器读出来的「这里可以绑什么」，**不含某个客户的设备或测点**。
2. **可视化实例**：租户从同一个模板，给不同客户各建一份可看的画面。实例挂在已有的平台拓扑上，不要另造一套场景模型。
3. **租户配置**：由租户在工作室里完成——选模板、为某客户创建实例、在该客户数据权限内绑定设备、图表卡片值和 3D 操作。
4. **客户观看**：客户只打开属于自己的实例来看（和被允许的操作）。不选模板、不改绑定、看不到「编辑」。

一句话：模板管「这幅 3D 画面能展示什么种类的对象」；实例管「这个客户实际连上了哪些设备和数」；权限管「这个客户能不能看见或操作这些数」。

「给客户选模板创建实例」按这个理解：**是租户为客户选用模板并创建实例**，不是客户自己去挑模板、自己做配置。若原意是客户也能自己选模板，需要再说明。

---

## 2. 模板是什么

模板是一类可视化的起点，不是某个客户的现场画面。

一份模板至少包括：

- 一份（或可替换的）GLB。权威结构仍是根节点 `extras.hmi`（本模型为 `hmi-scene/1`），由现有解析器读出可点选对象、行为、看板测点槽位。
- 风格套装（已有官方套装，如暖通 HUD、校园昼夜）。套装只负责观感，不是模板的全部。
- **绑定槽位**：解析器动态列出的「这个对象可以绑一台实时设备 / 这些测点 / 这些动作」。槽位来自模型 schema，不要在模板里写死 9 台模块机或固定图表种类。

模板里不要写入具体 `deviceId`、具体时间序列键、具体客户。这些属于实例。

同一份模板可以生成多个客户的实例。模板要有标识和版本：实例创建时钉住所用版本，避免模板以后改槽位时把已上线的客户画面悄悄改乱。第一版不自动把模板变更推到全部实例。

两种用法都要能说清，第一版可以先把第 1 种做扎实：

1. **同一份 GLB，多个客户实例**：比如同一园区模型，不同客户只看自己被授权的那部分设备和数据。
2. **同一套槽位，实例可换 GLB**：模板规定「机房类画面怎么绑」，某个客户的实例可以换成自己场站的 GLB，前提是仍能被同一 schema 解析出对应种类的槽位，再重新绑定。解析不出的槽位就不要装成还在。

---

## 3. 实例是什么（不要和拓扑、场景文档冲突）

现有两样东西都要继续用，不要再平行造第三套「场景」：

- **平台拓扑**：已经能记录场站、视图类型、范围 roots、风格套装和 GLB 引用。创建向导已经走这些接口。
- **场景文档 `SceneDocument`**：画面打开后的运行文档，绑定写在 `bindings` 里，不写回 GLB。

建议把 **一个可视化实例 = 一条平台拓扑 + 挂在这条拓扑上的绑定**。

- 租户从模板创建实例，本质是为某客户、某场站（及 roots）创建或关联一条拓扑，并引用模板的 GLB / 套装 / 槽位版本。
- 不要新建另一种「场景 ID」体系去和 `topologyId` 抢位置。3D-NGX 打开实例时，仍用拓扑 ID 去拉 GLB 和绑定。
- `SceneDocument` 仍是前端运行时文档：从 GLB 解析 + 套上该实例的绑定。它不是第二份平台主数据。

绑定目前还写在本机 `SceneDocument` 里。客户只读、换机器也能看到同一幅画面，就把绑定存到该实例（该条拓扑）上，由平台按登录身份下发。这是对「V1 绑定只留本地」的升级，**需要平台架构师一起定最小存储方式**，本方案先把分层说清，不单方面新增接口，确认前也不改代码。本机 IndexedDB 仍只作为明确失败时的降级，不能看起来像已经按客户发布成功。

---

## 4. 谁来配置、谁只看

| | 租户（配置） | 客户（观看） |
| --- | --- | --- |
| 选模板、创建 / 下线实例 | 要 | 不要 |
| 把实例分给某客户、某场站 | 要 | 不要 |
| 绑定设备、测点、卡片值、3D 动作 | 要，且只能选该客户权限内的实时设备 | 不要 |
| 进入工作室编辑态、看到右侧绑定配置 | 要 | 不要，也没有「编辑」 |
| 打开实例看 3D、铭牌、底部抽屉、图表卡片 | 可以预览 | 要，只读自己的实例 |
| 启停等操作 | 按该设备权限 | 默认只看；仅当该客户对该设备有操作权限时，底部抽屉按钮才可按 |

客户登录后只能列出属于自己的实例，点进去就是观看态（等同运行态）：右侧整栏不出现，画布铺开，底部抽屉保留。看不到绑定配置，也不能改模板或换设备。

租户在工作室里给某实例做绑定，才进入编辑态，右侧出现「目标设备 / 行为 / 看板数据」。退出编辑后右侧再收起。点空白清选中，但不退出编辑。这些与 18:18 一致。

仍只用平台现有租户账号和客户用户，不另做一套 3D 用户库。登录仍是密码换平台令牌这一路，不在本方案里改成另一套登录。

---

## 5. 数据权限怎么落到设备、图表和操作

平台已经按身份区分设备列表：租户走租户设备接口，客户用户走该客户的设备接口，再排除虚拟设备。实例上的绑定和看板必须继续落在这套权限上，不要在 3D-NGX 里另做一份「客户可见表」去绕过平台。

租户为客户 A 配置实例时：

- 目标设备下拉只出现 **客户 A 权限内的实时设备**，不能把客户 B 的设备、也不能把虚拟设备绑进去。
- 测点、命令清单也只拉这台已选设备上、当前身份能看到的键和命令。
- 图表卡片的槽位仍由解析器按该 GLB 动态生成；卡片上的值只来自本实例已经绑上、且该客户有权读取的时间序列。没有权限或没有绑定，就空态或「暂无数据」，不要用模型里的样例值冒充现场值，也不要画出别的客户的数。

客户打开自己的实例时：

- 只用自己的登录身份去订阅遥测、拉历史、下发命令。前端不要缓存租户配置时看过的完整设备表。
- GLB 可以是同一份模型（园区还在），但未绑定、或绑定了却已无权限的对象：不显示该对象的实时铭牌和卡片，也不能操作。不要为了「看起来热闹」把别人的数据画上去。
- 底部抽屉的启停：先满足「有控制面板和屏幕」这条既有规则，再检查该客户对该设备有没有操作权限；没有就按钮不可用并说明原因。
- 场景总览、对象卡片里的汇总数字，只统计这个客户能看到的对象和数据，不能写死「设备总数 32」。

一个模板多个客户实例时，槽位可以相同（都是同一机房模型里的模块机、泵、阀），但每份实例的绑定和实时值彼此隔离。

## 6. 客户观看界面（浮动看板只是候选）

客户点进实例之后的画面，建议仍按 18:18 布局：

- 右侧不做「实时检测 / 历史数据」，也不留空栏。
- 铭牌只在指向或选中时出现。
- 底部抽屉点选升起、失焦缩回。
- 图表和卡片若要出现，采用此前草案里的 **画布内侧浮动看板**（点选后在画布右上出该对象的测点 / 历史卡片；右下「总览」看整幅实例的汇总）。这只是观看界面的候选，**用户未点头前不改页面、也不让 UI / 前端先做卡片**。

租户预览客户画面时，应能用「退出编辑」看到和客户相同的观看态，避免只在编辑态里检查效果。

---

## 7. 需要平台架构师一起定的点（本方案不擅自加接口）

下面几项会影响能不能真正做到「客户换机器也能只读看到」：

1. 实例是否就用现有拓扑记录，并补上「来自哪个模板版本、属于哪个客户」。若拓扑不宜加客户字段，再另议一层很薄的实例关联，但仍以 `topologyId` 为画面主键，不要第二套场景 ID。
2. 绑定（设备、测点、动作、卡片值）如何挂到该拓扑上，以及按租户 / 客户身份读写的权限。确认前，不要在 3D-NGX 里静默发明一套新的平台持久化 API。
3. 模板本身存在哪：是资产目录里的模板包（GLB + 套装 + 槽位说明），还是「标记为模板的拓扑」。建议模板不是已发布给客户的拓扑。
4. 租户为客户绑定时，除现有客户设备列表外，场站 / roots / 遥测 / 命令是否都已按客户权限过滤；缺的由平台补，不由前端猜。

这些定之前，3D-NGX 仍可继续按 18:18 收工作台布局；模板与实例不要开工写页面。

---

## 8. 明确不要做的

- 客户自己配置绑定，或在观看态看到「编辑」。
- 把模板写成写死台数、型号、测点名或图表种类的页面。
- 另造一套与平台拓扑、`SceneDocument` 平行的场景模型，或把 `workspace/frontend` 当成 3D 入口。
- 绑定虚拟设备，或为某个客户放开其他客户的数据。
- 把绑定写回 GLB。
- 用户确认前改页面代码，或让 UI / 前端先做图表卡片。
- 本方案范围内改登录协议，或另建 3D 用户库。

---

## 9. 确认之后怎么做

用户和平台架构师把分层、存储和权限对齐后：先补模板 / 实例的交互原型（租户选模板建实例、按客户权限绑定、客户只读观看），观看界面是否采用浮动看板一并在原型里定；再改 3D-NGX 向导和权限下的设备列表，最后才做卡片。仍只在 MacBook Pro 上做，不 git。
