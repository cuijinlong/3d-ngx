## 通过项

1. 底部浅色抽屉放启停和状态；点击对象上浮，失焦缩回，可留细提手。`workbench-search` 可见缩回后的提手；`workbench-empty` 是展开空态便于对照，方案已写明失焦仍会缩回。空态沿用「未选中设备」「未绑定」。启停只给同时有控制面板和屏幕的对象；泵 / 阀 / 管 / 三通写出「不提供启停」。命令在点选或刷新时匹配，不写死 start/stop id，不按 rpcMethods 生成，不写入行为表。
2. 浮动铭牌默认不显示，只在指向或选中时出现，失焦隐藏；牌上只有名称、运行徽标和已绑遥测，没有启停。泵 / PLC 用轻量连接签，同样显隐。
3. 右侧默认浏览态（实时检测 / 历史数据），点「编辑」才出目标设备 / 行为 / 看板数据，「退出编辑」回浏览。无看板 `data` 的对象不出模块机那套测点图表。

其它工作台布局保持不变。解析器统一解析、不能写死的原则已写入方案；稿图中的「设备总数 32」和状态 chips 是本模型实例 / 参考样式。

## 落地时注意（不挡通过）

1. 部分空态、泵、阀、管、三通稿图在前排机组顶部有淡淡铭牌残影，这是出图残留，不是规则。实现时必须完全隐藏未指向且未选中的铭牌，不要把残影做进页面。
2. 指向只显示铭牌，不升起抽屉；点击才升起抽屉。两者不要做成同一种交互。
3. 方案第 3 节末仍有一句旧文案：「未选对象时，右侧只留一句：在画面上点要连接的对象」。以第 3 节开头、第 7 节和稿图为准：未选中时右侧仍是浏览空态（「未选中设备」），不要先摊开绑定表。请 UI 设计改掉这句旧话，避免对照时歧义。
4. 未绑定或命令匹配失败时，底部启停按钮须不可用并说明原因。
5. 「设备总数」和状态 chips 必须按解析 / 绑定结果出，不要写死 32 或固定那一组状态。
