## 1. 先说结论

1. **不另造一套和平台拓扑平行的场景库。** 一个场景就是已确认的「一条平台拓扑 + 挂在这条拓扑上的绑定」（以及 V1 之后该实例上的小部件排版）。打开仍用 `topologyId`。租户创建和设计场景，客户不自己创建、不自己做配置；打开自己的实例后，可按 18:42 口径启停、下发已绑定命令。
2. **「场景管理」是租户配置入口**，加在租户页面的客户列表后面：每个客户一行后面有入口，点进去管理**这个客户**的场景。真正的创建、设计、分层跳转配置在 3D-NGX 里完成，不要把 3D 工作台做进平台 Vue，也不要把 `workspace/frontend` 当成 3D 入口。
3. **租户设计好再给对应客户用**，并指定该客户默认打开哪一个场景。客户进入后先打开默认场景，也可以在已分配给自己的场景之间切换；不能改默认、不能改跳转关系。调整（增删改、排序、指定默认、配分层跳转）只由租户做。
4. **场景不但按场站，还按设备分组树上的节点来定范围。** 创建设景时，租户选客户、场站，再选分组树上的一个（或一组）节点作为这条拓扑的 `roots`。可绑设备仍是该范围内的实时设备，虚拟设备排除。不要用 ThingsBoard 里几乎只有 All 的 entity group 来充当「设备分组」。
5. **点分区进入下一级，是场景与场景之间的跳转，不是写死的「楼栋 → 层 → 机房」。** 层数不固定，可以只有一层，也可以二、三级或更深。从下级必须能返回。五院「点楼栋先选层，再进机房」是这套交互的一个实例，见第 5 节。
6. **这是当前 V1（登录 / 向导 / 18:18 布局）之后的能力**，不要撑进本轮实现。小部件编排已确认同样放到 V1 之后，本方案里的每个场景都沿用那套编排和 18:18 工作台。默认场景和父子跳转的存储分层已于 20:17 确认（客户级默认指针、专用跳转关系，打开仍用 `topologyId`），落地仍等当前 V1 收口之后，现在不新增持久化接口。

## 2. 入口放哪，默认场景怎么指定

租户侧（平台租户页）：

- 在客户列表里，**每个客户一行的后面**增加「场景管理」，不要做成客户用户能看见的创建入口。
- 点进去进入 3D-NGX 的该客户场景管理：列出这个客户已有的场景、创建 / 下线、指定默认、进入设计、配置分层跳转。
- 侧栏若要有总入口，也放在客户列表之后，进去后仍先选客户，避免和「客户自己创建场景」混在一起。

一个客户可以有多条场景（例如场站总览、某分区、某机房）。列表里租户能：

- 看到名称、所属场站、绑定的分组节点、用的模板版本、是否默认。3D-NGX 里的选客户页和场景管理一律用卡片网格呈现（详见第 10 节），不用表格、不用纯文字列表，不要只做一张没有预览的空表
- **指定默认场景**：每个客户有且只有一个默认；客户从运行入口进来时打开这一条
- 调整列表顺序（影响客户切换列表的顺序）
- 未设计完的场景只留在租户这边，不要让客户在切换列表里看到（「草稿 / 已给客户用」怎么落存储，V1 之后和平台一起定，本轮不发明接口）

客户侧：

- 打开 3D-NGX 运行入口，先进入租户指定的默认场景
- 用顶栏的场景名 / 面包屑在已有场景之间切换，或在画面上点分区进入下级
- 没有「场景管理」，没有「编辑」，不能指定默认，不能改跳转，不能拖拽小部件
- 启停仍在底部抽屉，不做到场景切换或小部件上

租户预览客户观看态时，应能退出编辑，看到和客户相同的布局（右侧整栏不出现，画布铺开，底部抽屉保留），并按客户的默认场景和跳转走一遍。真正的客户视野仍以该客户账号打开为准。

## 3. 场景按场站和设备分组节点怎么组织

创建或调整一条场景时，范围这样定（沿用已有拓扑字段，不另造范围模型）：

```
客户 → 场站（siteId）→ 设备分组节点（作为拓扑 roots）→ 本条场景（topologyId）
         └── 同一场站下可以有多条场景，分别钉在不同的分组节点上
```

平台已有的设备分组树，维度包括分项、区域、用能性质、空间位置（例如某栋、某办公区、某锅炉房）。列出某节点下的子级，现成接口是 `GET /api/energy/child-relations` 和 `GET /api/energy/entity-briefs`；按场站加视图取范围选项，现成接口是 `GET /api/energy/topologies/scope-options`。创建拓扑时把选中的节点写成 `roots`。不要新做一套 3D 专用分组接口，也不要把 ThingsBoard 的 entity group 当成这棵树。

可绑设备 = 该客户名下的实时设备 ∩ 该场站 ∩ 这些分组节点子树。`listRealtimeDevices` 今天主要以 `siteId` / `topologyId` 为参数；按某一个分组节点筛时，前端可用现有 `child-relations` 走到设备 id，再与实时列表求交，或先用该节点作为 `roots` 建成图，再按 `topologyId` 拉可绑列表。

同一场站、同一份园区模型，也可以给不同客户各建实例（V1 之后允许创建时单独指定拓扑的 `customerId`，不要在 `additionalInfo` 里再写一份）。模板仍是 GLB + 未绑定槽位 + 风格套装；实例创建时钉住模板版本，再按这个客户、这个场站、这些分组节点去绑设备和测点。

## 4. 二 / 三级跳转与返回怎么交互

工作台骨架仍守 18:18：预览 / 运行右侧整栏不出现，画布铺开；只有编辑态才出右侧绑定配置；点空白不退出编辑；底部抽屉三态保留。场景切换和面包屑放在**顶栏**（或画布上很轻的一层），不要为此恢复右侧栏，也不要搬回旧遥测栏。

```
┌─ 顶栏：场站总览 / 某分区 / 某机房    查找 · 编辑（仅租户）… ─
│ 最左导航 │  小部件仍围在画布四周（V1 之后已确认的编排）        │
│          │                                                     │
│          │              当前这一级的 3D 场景                    │
│          │         点已配置的分区 → 进入下级（或先选一层）       │
│          │                                                     │
│          │  ▬▬ 底部抽屉（启停 / 状态） ▬▬               总览    │
└──────────┴─────────────────────────────────────────────────────┘
```

**进入下级（观看态，租户预览和客户相同）：**

- 点画面上的某个分区（楼栋、区域、机房入口等，以租户配置为准，不写死对象名）：
  - 只配了一个下级场景：直接进入那条场景；
  - 配了多个下级（例如一栋楼下有若干层或若干机房）：先在画面上出一份轻量选择（列表或等效控件），选中后再进入；没有可进的下级时，只选中该对象（镜头和铭牌），不跳转；
  - 未配置跳转的对象：行为与现在一样，只选中，不跳。
- 不要一点分区就自动钻到子树里「第一个有场景的节点」——五院院区曾经因此从楼栋直接跳进机房。有中间层就要先选，再进。
- 跳转在当前页完成，不要新开窗口。

**返回与切换：**

- 顶栏用面包屑表示当前路径，例如「场站总览 / 某分区 / 某机房」。点上级名称即返回那一级。也可提供返回上一级。
- 从下级返回上级时，尽量回到离开前的视角，并保持当时的选择（例如仍停在刚才那栋 / 那一层），不要把人丢回默认镜头后还要再找一遍。
- 同一客户下没有父子关系的场景，可通过顶栏场景名打开切换列表，按租户排好的顺序列出「已给该客户用」的场景。

**租户如何配置这些跳转（只在编辑态）：**

- 在上级场景里选中一个可点对象，在右侧配置里增加「进入场景」（或等价项）：指定一个下级场景，或指定一组可选项（选项仍是已有的场景，标签由解析结果或分组节点名称来，不要写死「1F / 2F」）。
- 控制面板和屏幕仍不单独作为跳转目标，点到它们还是选中所属设备。
- 内容同样由解析器和绑定动态生成，不能写死台数、型号、分区名或层级数。

层数不封顶为三，也不要求每个项目都有三层。只有一条场景时，没有分区跳转，只保留默认打开和（若有多条互不从属的场景时的）切换。

## 5. 五院「点楼栋先选层，再进机房」怎么一般化

五院那次是同一类导航：点一栋楼不要直接进机房，先选出这一栋下面可去的层或房间，有场景才出现「进入」，从机房要能回到原楼、原层。

本方案把它收成三条通用规则，不把「楼栋 / 层 / 机房」写进产品规则，也不复用五院那套旧空间树接口（`/gtems-api/spaces/tree` 属于另一套院区产品，不是现在的平台拓扑）：

1. **点上级对象本身不自动跳。** 先选中，再根据租户配置决定：没有下级就只定位；有一个下级就进入；有多个下级就先出现选择。
2. **中间选择的选项来自配置和解析，不来自写死的楼层表。** 可以是层，也可以是分区、屋面、地下机房等——取决于这条场景下租户挂了哪些下级、分组树上有哪些子节点。
3. **返回要回到离开前的那一级、那个选择。** 面包屑和返回都走场景之间的父子关系，不靠页面写死「从机房一定回到院区」。

天骄科技园若以后要「从园区总览进某机房」，也走同一套配置，而不是再做一份只给天骄用的跳转。

## 7. 前端怎么表现，哪些按已确认分层落地（现在不发明接口）

**现有能力已经够用、前端先按这个表现的：**

- 场景主键仍是 `topologyId`；场站、`roots`、套装、GLB 引用继续用现有拓扑字段
- 按场站和设备分组节点定范围：`scope-options`、`child-relations`、`entity-briefs`，再与客户实时设备列表求交
- 租户为客户 A 配置时，设备下拉仍走 `GET /api/customer/{customerId}/devices`，不要用租户全量
- 登录仍是已对齐的密码 → JWT；客户打开场景用自己的票

**产品交互已确认；存储分层已于 20:17 确认，落地仍等当前 V1 收口之后、现在不发明接口的：**

1. **默认场景存在哪。** 每个客户一条「默认打开的 `topologyId`」，由租户写、客户只读。不要在 `additionalInfo` 里再写一份和资产 `customerId` 打架的客户字段。
2. **场景之间的父子 / 跳转关系存在哪。** 例如上级拓扑上记下：哪个画面对象（或哪个分组节点）进入哪一条下级拓扑，多个下级时选项是什么。这是实例级配置，建议挂在该条拓扑上，与绑定、小部件排版一起由租户写、客户只读，不写回 GLB。
3. **未给客户用的草稿场景如何在列表里区分**，避免客户切换列表看到未完成的设计。现有拓扑还没有「模板 / 草稿 / 已发布」状态。
4. 若租户配置时需要一次拿回整棵设备分组树，而现有接口只能按节点逐级取子级，是否要在 V1 之后补一棵只读树，由平台定；前端不单方面新造分组 API。
5. 同一场站给多个客户各建场景时，仍按已对齐口径：V1 之后允许创建时单独指定拓扑的 `customerId`。

产品交互和存储分层都已确认。现在仍不改页面，也不新增持久化接口。本机 IndexedDB 只作为明确失败时的降级，不能看起来像已经按客户发布成功。

## 10. 补充（2026-11-21，Asia/Shanghai，体验修订）

对照实装见 `3D-NGX-体验修订-视觉与交互.md` 与 `mocks/ux-20261121/`。第 9 节已确认的五条产品口径不变：不另造场景库、客户仍不创建场景、跳转与返回规则不变。下列只补视觉、文案和壳，便于和当前页面对照。

**入口页一律用卡片。** 能不用列表就不要用列表。3D-NGX 里的选客户、场景管理及同类清单页一律用卡片网格，不用表格，不用纯文字列表，也不用图文行回潮成名单。空态用卡片页上的空说明，不要空表。平台租户客户列表每一行后面加「场景管理」的口径不变（那是平台页，不是 3D-NGX 选客户页）。工作台画布四周仍是已定的「左右翼 + 中央主视觉」，小部件编排规则不改。

**选客户。** 做成卡片网格，不要客户名单表。每张卡：客户名、场景数量或默认场景提示（还没有指定默认时写「还没有指定默认场景」）、入口「场景管理」。稿图见 `mocks/ux-20261121/customers-cards.jpg`。

**场景管理摆放。** 带 16:9 缩略预览的卡片网格。学的是「整屏缩略图 + 名称 + 状态」的摆放，不是参考站配色。浅色卡、主色 `#1657e8`、走 `--ngx-*`。每张卡：缩略（能看出主画面和四周图表更好；还没预览时用视口衬底色 + 「暂无预览」，不要用深色科幻封面冒充）、场景名、徽标「默认」「未落库·本地草稿」（仅实际有时出）、操作（打开 / 设为默认等）。场站、分组节点、模板版本放在卡内次级信息里，不要丢。

**空态文案。** 还没有指定默认时，写「还没有指定默认场景」，不要写「默认场景指针为未落库 / 本地草稿」。空态主句可保留「该客户还没有可管理的三维场景，可以新建一个。」真有本地指针时，再标明「未落库 / 本地草稿」，并且列表里必须能看到对应那一卡。

**面包屑。** 必须写出客户名，例如「平台演示中心 / 场景管理」。不要只写一个没有名字的「客户」。若确实没有客户名，面包屑应是可点的「选择客户」，不要出现光秃的「客户」。租户还没明确选过客户时，先落到选客户页；票里的空的或公共 customerId 不算已选客户。从平台带着真实客户 id 点进来的口径不变。路径落点由前端按此规则走。

**新建场景弹窗。** 「取消」「创建场景」钉在弹窗底部（固定脚），首屏永远可见；中间表单区可滚，不要把按钮滚出去。把「创建新拓扑（把上面的范围作为 roots 提交）」改成「创建新拓扑」，说明文案：「用上面选的场站和分组作为这个场景的范围。」场景名称不要默认填「新建工业场景」；留空，占位符「给这个场景起个名字」，必填。

**打开失败页。** 壳与场景管理、工作台同一套顶栏，不要旧窄侧栏。标题可为「打开失败」。正文按原因分条（前端按实际原因挑一条，不要只写「无法打开该场景」）：找不到这个场景；这个场景不属于当前客户；暂时连不上服务，请稍后重试；打开超时，请刷新或返回场景管理；原因不明时：打不开这个场景，请返回后重试。按钮：「返回场景管理」（落点按刚才在管的客户走；没上下文回选客户；不要回到无名客户）。可加「刷新重试」。

**设置入口。** 场景管理以及选客户的顶栏，在亮色 / 深色旁、退出之前加「设置」。设置页壳见《3D-NGX-登录与入口方案.md》第 9 节，以及体验修订。

**全局失败与加载超时。** 热更新、运行态崩溃或意外错误，用同一套顶栏的中文失败页，文案见体验修订，不要把英文开发者堆栈给到现场。加载超过约 15 秒要改成失败或空态并给返回，不要只剩「加载中」。
