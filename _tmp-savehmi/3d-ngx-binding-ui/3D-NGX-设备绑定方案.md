# 3D-NGX 设备绑定界面方案

面向前端可直接落地。对照来源：能源卫士仪表板「某市热力 · 二号换热站组态」，在 SCADA 符号上点编辑后，右侧「目标设备」「行为」。交互只对齐这套绑定逻辑，不搬平台皮肤，也不做抽屉。产品名是 3D-NGX，主色 `#1657e8`（savehmi 工业风）。本方案不改仓库代码。

对照截图在同目录 `refs/`。

## 1. 要做成什么样

右侧仍是场景对象的「设备绑定」台，不是独立抽屉，也不是场景编辑器。选中一个 3D 对象后，面板只有两块主内容：

1. **目标设备**：先定绑哪台实时设备（可直接选设备，也可用实体别名）。
2. **行为**：再定这台设备如何驱动对象的运行 / 预警 / 告警 / 动画，以及点击时做什么。

下面可保留次要区块 **测点显示**（把设备测点接到模型接口，供 HUD 读数），不要再把「一个设备下拉 + 一堆原始键名 / 指令 / whenValue」堆在第一屏。

不要出现移动、旋转、缩放。不要出现「按模型创建模拟设备」。虚拟设备不进绑定列表。

## 2. 平台上实际看到的逻辑

只读查看，未点「应用 / 保存 / 拒绝」，也未改设备管理。当前符号是 Left motor pump，目标设备走的是「实体别名」。

### 2.1 目标设备

- 分段开关：**设备** | **实体别名**（当前为实体别名）。
- 实体别名已绑：`2#换热站控制器`，可清除、可编辑。
- 「编辑别名」对话框字段：
  - 别名名称（例：`2#换热站控制器`）
  - 开关：解析为多个实体（当前关）
  - 过滤器类型（当前：单个实体；平台还有大量 ThingsBoard 过滤器）
  - 类型（当前：设备；平台还有资产等实体类型）
  - 设备（当前：`HX2-StationController`）
  - 取消 / 保存

本页设备下拉里只看到已选的 `HX2-StationController`，未能在列表里直接核对此处的「实时 / 虚拟」标记。3D-NGX 仍必须只用平台「组织-场站-设备管理」里的实时设备；虚拟设备仅用于手动上报。现有代码已有 `isRealtimePlatformDevice`，列表按它过滤即可。

### 2.2 行为（状态类，同一套编辑器）

行：运行中、警告状态、严重状态、严重状态动画。每行右侧是摘要 + 编辑。

当前实例：

- 运行中：使用时间序列 `pump1_running`
- 警告状态 / 严重状态 / 严重状态动画：常数 `False`

点「运行中」编辑后的字段：

- 操作（当前：获取时间序列）
- 时间序列键*（可搜索，占位「键名称」，当前 `pump1_running`）
- 操作结果转换器：无 | 函数（当前：无）
- 当结果为「运行中」时：类型「布尔值」，值 True / False（当前 True）
- 取消 / 应用

状态类「操作」全集（平台原样，3D-NGX 不要全搬）：

- 不执行操作
- 获取属性
- 获取时间序列
- 获取告警状态
- 获取仪表板状态 ID
- 获取仪表板状态对象

选「不执行操作」时，编辑器改成给一个常数「值」True / False（警告 / 严重目前就是这样，行上显示 False）。

临时切到「获取属性」（随后已取消，未应用）时，字段变为：

- 属性范围（当前「任意」）
- 属性键*
- 操作结果转换器：无 | 函数
- 当结果为「…」时：布尔值 True / False

### 2.3 行为（点击，另一套操作）

当前摘要：无操作。编辑器只有「操作」+ 取消 / 应用。

平台「点击」操作全集（几乎全是仪表板导航，不是下发设备指令）：

- 无操作
- 导航到新的仪表板状态
- 更新当前仪表板状态
- 导航到其他仪表板
- 自定义操作
- 自定义操作（带 HTML 模板）
- 移动端操作
- 打开 URL
- Save browser location

这些不能原样搬进 3D-NGX，见第 9 节。

### 2.4 不要搬进绑定台的部分

右侧同时还有「外观 / 卡片外观 / SCADA 符号」，那是组态部件皮肤，不是绑定逻辑。3D-NGX 里被选中的已经是场景对象，不必再选符号。

## 3. 右侧面板结构

宽度与现有右侧栏一致，白底，分段清晰。选中对象后的顺序：

```
设备绑定
  当前对象：{场景对象名称}

目标设备
  [ 设备 ] [ 实体别名 ]
  …选择区或已绑定摘要…

行为
  运行中            {摘要}  编辑
  警告状态          {摘要}  编辑
  严重状态          {摘要}  编辑
  严重状态动画      {摘要}  编辑
  离线              {摘要}  编辑
  点击              {摘要}  编辑

测点显示（次要，可默认折叠）
  模型接口 ↔ 设备测点

解绑
```

未选对象时：说明「在场景里点选要绑定的对象」，可保留「按名称自动连接」作为批量辅助（只匹配实时设备）。不要在未选对象时展示空的行为编辑器。

## 4. 目标设备怎么做

分段开关与平台一致：**设备** | **实体别名**。

### 4.1 模式：设备

一个可搜索下拉，只列出实时设备。推荐展示：设备名称、设备类型。无结果文案：「没有可绑定的实时设备」。列表下用一行说明：「只能绑定实时设备。虚拟设备用于手动上报，不会出现在这里。」

已选中时，行内显示名称，可清除、可重选。

### 4.2 模式：实体别名

V1 只保留与当前实例相同的心智模型，做成「别名 → 一台实时设备」，不要引入平台那套完整过滤器引擎。

绑定摘要行：别名名称（如 `2#换热站控制器`），可清除、可编辑。

编辑用轻量弹层（不必抽屉），字段只有：

- 别名名称*（文本）
- 设备*（与 4.1 相同的实时设备下拉）
- 取消 / 保存

不要做：解析为多个实体、过滤器类型（设备类型 / 关系查询等）、实体类型（资产 / 实体视图等）。若后续确实需要，先走第 9 节讨论。

### 4.3 异常

- 当前绑定指向虚拟设备：红色提示「这台是虚拟设备，不能用于 3D 绑定，请改绑实时设备」，测点和行为禁用，只留「重新绑定 / 解绑」。
- 设备已删除或平台读不到：提示失效，允许重选。
- 未选目标设备时，行为区禁用，说明「先选择目标设备」。

## 5. 行为怎么做

每行左侧是行为名，右侧是一句人话摘要 + 编辑按钮。编辑用锚定在该行的轻量弹层，底部是「取消 / 应用」，与平台一致：点应用才写入，点取消不改。

### 5.1 状态类（运行中、警告状态、严重状态、严重状态动画、离线）

3D-NGX V1 状态是 运行 / 预警 / 告警 / 离线。平台这个符号没有「离线」行，建议 3D-NGX 补上，默认「取设备在线状态」，也可改绑时间序列或属性。

V1 开放的「操作」：

| 操作 | 出现的字段 | 说明 |
| --- | --- | --- |
| 不执行操作 | 值：True / False（或关） | 与平台警告/严重一致，用于恒开/恒关 |
| 获取时间序列 | 时间序列键*（来自该设备测点） | 主路径，对标 `pump1_running` |
| 获取属性 | 属性键*；若后端有范围再显示「属性范围」，默认任意 | 对标平台「获取属性」 |
| 获取告警状态 | 告警级别：预警 / 告警 | 平台有此项，且产品已有告警模型，V1 可做 |
| 取设备在线状态 | 无额外键（仅「离线」行默认项） | 平台没有，3D-NGX 补，用来驱动离线态 |

不要在 V1 做「获取仪表板状态 ID / 获取仪表板状态对象」。

共用字段：

- 操作结果转换器：V1 只提供「无」。不要做平台的「函数」（脚本转换）。
- 当结果为「{行为名}」时：V1 先做布尔值 True / False。若测点是数值或文本，可用简单比较（等于 / 大于 等），复用已有 `StatusRule`，不要先上脚本。

行上摘要规则：

- 获取时间序列：`使用时间序列「pump1_running」`
- 获取属性：`使用属性「…」`
- 获取告警状态：`使用告警「告警」`
- 不执行操作 + False：`False`（或「未启用」）
- 不执行操作 + True：`True`（或「恒为是」）
- 取设备在线状态：`使用设备在线状态`
- 未配置：`未设置`

语义约定（写进产品和代码注释）：

- 运行中为真：对象进入运行态
- 警告状态为真：预警
- 严重状态为真：告警（严重优先于预警）
- 严重状态动画为真：在告警外观上叠加模型动画（对应现有 `actionMappings` 的播放条件）
- 离线为真：离线态（若同时满足告警，告警优先，离线作为连接态提示）

### 5.2 点击

平台点击操作是仪表板跳转，不能当 3D-NGX 的点击菜单。3D-NGX 点击应对齐产品已有的「下发指令」，操作只有：

| 操作 | 出现的字段 |
| --- | --- |
| 无操作 | 无 |
| 下发命令 | 命令*（来自该设备 `listCommands`），必要时附参数 |
| 打开设备详情 | 无额外字段（打开右侧/浮层里已有的设备信息，不做新浏览器跳转） |

不要做：导航到仪表板状态、其他仪表板、自定义 HTML、移动端操作、打开 URL、Save browser location。若以后要「打开 URL」，先讨论（第 9 节）。

点击摘要：`无操作` / `下发「启动」` / `打开设备详情`。

## 6. 空态与已绑定态

| 状态 | 面板表现 |
| --- | --- |
| 未选场景对象 | 空态文案 +「按名称自动连接」 |
| 已选对象，未绑设备 | 目标设备为空；行为禁用 |
| 已绑实时设备，行为未配 | 目标设备显示名称/别名；行为多为「未设置 / 无操作 / False」 |
| 已绑且已配行为 | 行为行显示人话摘要，如「使用时间序列「pump1_running」」 |
| 误绑虚拟设备 | 错误提示，强制改绑 |

## 7. 视觉

沿用 savehmi，不要 Savior 品牌：

- 主色 `#1657e8`，悬浮/强调 `#2f6bff`
- 正文 `#1f2329`，次要文字 `#5f6e84`
- 成功 `#19b37d`，危险 `#e5484d`
- 背景 `#ffffff`，面板底/分割 `#edf1f7`
- 分段开关、主按钮用主色；「解绑」用危险色文字按钮，需确认
- 弹层圆角 8px，阴影克制，标题就是行为名或「编辑别名」
- 不要emoji、不要紫渐变、不要装饰插画

同目录 `preview/index.html` 是静态示意（空态 / 已绑定 / 运行中编辑弹层 / 编辑别名），按它还原间距和层级即可。

## 8. 和现有数据怎么接（建议增量，不推倒）

现有 `DeviceBinding` 已有 `deviceId`、`deviceName`、`telemetryMappings`、`actionMappings`、`statusMapping`。建议只做加法，不要先删旧字段：

```ts
targetMode?: "device" | "alias";
aliasName?: string;

type BehaviorOp =
  | { op: "none"; value?: boolean }
  | { op: "timeseries"; key: string }
  | { op: "attribute"; key: string; scope?: "any" | "client" | "server" | "shared" }
  | { op: "alarm"; level: "warning" | "alarm" }
  | { op: "connectivity" }; // 仅离线

type BehaviorWhen = {
  valueType?: "boolean" | "number" | "text";
  operator?: "eq" | "gt" | "gte" | "lt" | "lte";
  value: boolean | number | string;
};

behaviors?: {
  running?: { source: BehaviorOp; when?: BehaviorWhen };
  warning?: { source: BehaviorOp; when?: BehaviorWhen };
  alarm?: { source: BehaviorOp; when?: BehaviorWhen };
  alarmAnimation?: { source: BehaviorOp; when?: BehaviorWhen };
  offline?: { source: BehaviorOp; when?: BehaviorWhen };
  click?:
    | { op: "none" }
    | { op: "command"; commandId: string; commandParams?: Record<string, unknown> }
    | { op: "openDetails" };
};
```

读写约定：

- 测点显示继续写 `telemetryMappings`（模型接口 ↔ 测点）。
- `behaviors.alarmAnimation` 为真时，可继续驱动已有 `actionMappings` 的播放条件，不必另做一套动画系统。
- `behaviors.click.command` 对应已有 `commandId` / `commandParams`。
- 旧的单键 `statusMapping` 可暂时由运行中/警告/严重回写生成，或只读兼容；若要废弃，先讨论。
- 设备列表继续 `devices.filter(isRealtimePlatformDevice)`。
- 「按模型创建模拟设备」从本面板移除。

## 9. 会影响架构、先讨论再做的点

下面这些**不要在这次绑定台里直接做**：

1. **完整实体别名过滤器引擎**（解析为多个实体、多种过滤器类型、资产/实体视图等）。V1 只做「别名名称 + 一台实时设备」。
2. **把平台点击菜单原样搬过来**（仪表板状态导航、自定义 HTML、移动端操作、打开 URL 等）。3D-NGX 点击先做「无操作 / 下发命令 / 打开设备详情」。
3. **获取仪表板状态 ID / 对象**。这是组态页内部状态，不是 3D 场景能力。
4. **操作结果转换器 = 函数**（用户写脚本）。V1 只用「无」，数值/文本用简单比较。
5. **用绑定台改设备管理里的实时/虚拟标记**。绑定台只消费，不维护设备。

若产品坚持要其中某一条，先定范围再改类型和接口。

## 10. 明确不做

- 不改仓库代码（本方案只出界面与字段约定）
- 不做移动 / 旋转 / 缩放
- 不绑虚拟设备，不在本面板创建模拟设备
- 不把「外观 / SCADA 符号」做成绑定字段
- 不用抽屉（逻辑对齐即可）
- 不把登录口令写进方案、预览或截图
